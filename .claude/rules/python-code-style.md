# 代码样式指南
本文章内容主要描述了针对于python代码编写的样式风格指导.

## 方法注释
每一个function都需要添加方法注释,需要简述当前方法的功能、所有形参的含义、异常抛出的细节以及返回结果的细节.
- 示例1: 
```python
def acquire_scaling_lock(
    lock_name: str,
    lock_id: str = '',
    expired: int = 600
) -> str:
  """添加伸缩操作锁

  @param lock_name: 锁名
  @type  lock_name: str
  @param lock_id: 锁值, defaults to ''
                  如果未提供锁值,则会自动生成一个锁值
  @type  lock_id: str, optional
  @param expired: 锁的过期时间, defaults to 600
                  以秒为单位, 默认为10分钟/600秒
  @type  expired: int, optional

  @raises: 操作redis失败
  @type:   exception.tool.AcquireScalingLockException
  @raises: 若加锁失败
  @type:   exception.tool.AcquireScalingLockException

  @return: 加锁成功后, 会返回锁值
  @type:   string
  """
```
- 示例2: 
```python
@abc.abstractmethod
def set_destroyer(self):
  """设置弹性缩减器

  在该方法中,需要创建相应的弹性缩减器对象实例,且必须要赋值给对象实例属性destroyer,即self.destroyer;

  注意,弹性缩减器对象实例所属类必须为zonebank.destroyer.base.BaseDestroyer的子类.

  弹性缩减过程中需要的数据,可通过弹性缩减器的对象实例属性来进行传递和设置.
  不同的弹性缩减器可能会有着不同的对象实例初始化过程,这完全取决于相应弹性缩减器的实现.
  会议集群相关的数据可通过对象实例属性zone来获取,即self.zone.

  此外, 还需要设置会议服务资源的基础类型;
  因为基础类型会影响弹性缩减操作的相关分支判断;
  可调用对象实例方法: self.set_service_base_type()来进行设定;
  具体的设定方式请查看self.set_service_base_type()与class ServiceBaseType;
  """
```
- 示例3:
```python
def __init__(self, data=None, notify_method_configs: dict = {}) -> None:
  """构造方法

  为了保证Notifier类对象实例在进行init操作时的一致性,
  因此将NotifyMethod类的配置参数放入到self.data属性中传入到Notifier类对象中;
  即没有特殊需求, 不建议开发者重写init方法.

  对于所依赖的NotifyMethod类对象的配置;
  可通过对象实例方法set_notify_method_default_configs和set_notify_method_configs方法来实现;
  具体的使用方法请见这两个方法的方法注释.

  @param data: 通知内容/数据, defaults to None
  @type  data: dict, optional
  @param notify_method_configs: 通知操作类配置项, defaults to {}
                                该参数内部的数据结构,
                                与set_notify_method_default_configs的实现细节相关;
                                应是set_notify_method_default_configs内包含的配置项的子集;
                                即需要外界自定义(不使用默认值)的配置项应该定义在该参数中;
                                注意,
                                配置项名称(key)应与set_notify_method_default_configs保持一致;
  @type  notify_method_configs: dict, optional
  """
``` 

## 类注释
每一个自定义class都需要添加注释,需要说明当前类的用途以及其可能存在的业务含义.
- 示例1: 
```python
class Timer():
    """弹性伸缩计时触发器

    若需要修改timer的实现方式(runtime),则只需要修改当前类的类属性TIMER_RUNTIME_CLASS即可;
    即将自定义实现的runtime类通过该类属性依赖注入到timer中;
    其中,自定义runtime必须继承models.timer.runtime.BaseTimerRuntime类进行实现.
    默认的timer是基于tencent cloud的scf来实现的.
    """
```
- 示例2: 
```python
class BaseDecreaseQueryStrategy(abc.ABC):
    """弹性缩减中所使用的会议服务资源查询获取策略抽象基类

    在进行弹性缩减的动作之前,需要确定要删除那些会议资源服务;
    不同种类的会议服务、或是不同的会议集群可能有着特殊的删除资源规则;
    例如按照会议服务资源创建的时间来过滤查询,或是按照指定的资源类型来过滤查询等等.
    为了实现能够具备满足各种查询获取需求、能够快速支持对接各种策略的功能;
    即抽象出当前概念，用于封装各类查询获取需求.

    每个策略类所需要的特殊数据可将其实现为该类的实例对象属性,并通过重写构造方法来从外界接收这些数据.
    """
```
- 示例3: 
```python
class BaseDecreasePolicy(abc.ABC):
    """弹性缩减策略抽象基类
    所有的弹性缩减策略在实现前,都应先继承该抽象基类;
    弹性缩减策略会依赖于两类数据: 策略参数和策略数据.

    策略参数是指在不同策略执行中所使用到的专用参数;
    不同的策略逻辑会使用到各自所需的参数,例如集群名,服务类型和策略配置等;
    这些参数应该被设计为该策略类的对象实例属性;
    并通过重写构造方法: __init__(),在类初始化阶段来将这些专用参数传入策略类中;
    注意重写构造方法: __init__()时需要调用基类的构造方法,以确保创建相应的实例属性.

    策略数据指的在策略执行时所依赖的基础数据,例如集群当前的负载数据;
    策略数据一般为真实数据.
    
    由于每种弹性缩减策略都会依赖于不同的策略数据;
    因此需要实现获取策略数据的相关逻辑,这些逻辑应被封装到实例方法: get_policy_data()中;
    在该方法中,应将获取到的数据保存在实例属性policy_data中;
    同时也可将数据作为方法返回值返回给调用者.

    每种弹性缩减策略都应该实现一个决策逻辑方法: decide();
    该方法需要将决策结果返回给调用者;
    即每一个策略的核心逻辑应在该方法中实现.
    """
```

## 代码目录结构
- 在构建代码结构目录时, 应根据所需要完成的功能模块名称建立对应的模块目录.
- 尽可能保证项目的根目录下没有过多零散的代码文件.代码文件应该尽可能的规整到相应过的子目录内.
- 对于抽象类或基础类的代码文件,应该存放于相关目录中的base/目录下
- 对于实体类的代码文件, 存在于对应的模块目录下即可.
- 测试相关的代码文件应该存放于test/目录内.并且在内部应根据测试需求建立子目录来存放和整理.
- 如果使用了开源框架, 则应尽可能保证不改变原有框架内的目录结构上, 创建项目自身的代码文件目录.
- 相关的文档与图片应存放于项目根目录中的docs/目录中.```这条规则不适用于README.md, README.md存放在项目的根目录中即可```.
- 工具类型的功能代码应存放于相对目录中的tools/目录下.
- 项目所产生的日志应存放于项目根目录中的logs/目录下.
- 项目所需的配置文件应存放于项目根目录中的conf/目录下.
- 项目相关的异常类实现代码应存放于项目根目录中的exception/目录下.
- 若项目有产出物,则这些产出物应存放于项目根目录中的指定子目录中.具体的子目录根据产出物类型来进行建立.

## Mixin类使用技巧
如果需要为一个类增加一些功能方法时, 应优先考虑通过实现一个或多个Mixin并且继承它们来实现。

## API文档编写技巧
在完成一些带有API功能的项目时,如果需要为这些API编写说明文档,可以考虑引入swagger.

## 重试机制实现技巧
- 如果某些功能内需要实现重试机制的相关功能时, 可以考虑使用```指数退避算法``来进行实现.
- 推荐将指数退避算法独立实现为一个通用方法.

## 面向对象编程技巧

### 组合与聚合的选择思路
- 在进行面向对象编程中, 请优先选择聚合的方式来实现多个类对象之间的配合.
- 在使用聚合时, 优先选择以依赖注入的方式来实现.
- 针对关系较强的多个类对象时, 请使用组合的方式来实现它们之间的联动/配合.

### 设计模式的选择
- 在一个功能实现中如果大量出现了if else的结构时,则应该考虑改用策略模式来重构这段代码
- 如果需要对已存在的代码进行功能扩展, 此时应该考虑使用装饰器模式来实现.如果是扩展一个方法,则也可以直接使用python的装饰器功能来实现.
- 如果一个需求可能有多种实现方式,并且可能会频繁更换这些使用方式时,应该选择使用策略模式来实现这个功能需求.

### 构造方法形参的默认值
- 如果构造方法中的形参与项目中的配置项有关联, 则不要为这些形参配置有实际意义的默认值; 而是使用类似于None来作为默认值. 同时,应在构造方法中通过None来判断是否成功加载/传入了配置项.

## 异步实现的选择
如果选择使用异步的方式来实现功能时,请务必要先检查该功能所依赖的对象、服务以及其他都能够满足/实现异步的要求.例如当在调用一些第三方lib中,如果这些第三方lib本身不支持异步调用,则及时使用了异步的方式,实际上最后依旧还是一个串行执行的功能.

## 并发实现细节
当选择使用多进程或多线程实现某些功能时,若没有特殊要求,则首选使用python内置的进程池和线程池,即内置concurrent.

## 动态映射
当需要实现动态映射时, 则可以选择使用反射机制来进行实现.但需要注意的是, 使用反射机制时请务必与开发者讨论清楚其中的安全隐患.

## 日志记录
- 在功能类中不进行日志记录, 只进行异常捕获和向上抛出.
- 日志记录只实现在最外层的调用代码中.

## 日志格式
若用户没有特殊要求, 则使用如下日志格式:
1. format: ```"%(asctime)s [%(levelname)s] %(thread)d %(funcName)s:%(lineno)d %(message)s"```
2. handler: ```logging.handlers.TimedRotatingFileHandler```. 相关参数为: when='D', interval=1, backupCount=7, encoding='utf-8'.

## 异常捕获
最外层的调用代码要保证存在一个“兜底”形式的异常捕获, 保证不会丢失任何来自于内层被调用者抛出的异常.

## 编码尺度
- 若实现的只是一个不常用的小工具, 则应该选择使用面向过程的编程方式来进行实现.
- 若实现的是一个可能被复用的功能, 则应该选择使用面向对象的编程方式来进行实现.
- 如果实现的是一个系统级别的需求, 则必须使用面向对象编程来进行设计与实现.要保证系统内各个模块都具有“高内聚,低耦合”的特性, 保证模块的高复用性.

## 文本查找与比对
在不使用数据库的前提下, 如果需要实现文本查找与比对的功能时, 请务必使用正则表达式来进行实现.

## 注释编写技巧
- 注释的内容必须要满足具有**增强可读性和可解释性**的内容特点.
- 要尽可能避免存在无用注释.
- 注释的语言首选为中文.**但要注意: 注释内容中关于代码的部分请使用英文来描述, 不需要强制翻译为中文描述.**
- 对于容易被误解读的代码段, 务必要加上注释说明
- 对于接口类型的代码段, 请加入注释说明.
- 当一段代码有着过长的内容、或是存在过深的调用逻辑时, 请添加注释来说明代码层次.

## if/else的使用
1. 要避免存在过深的if/else嵌套结构.这里的过深指的是超过3层嵌套关系.
2. 要避免存在过长的if/else/else if的结构.这里的过长指的是超过3个else if的语句使用.
3. 当出现上述1与2中的情况时,请尝试使用以方法来重构问题代码:
- 使用卫语句
- 使用map结构/switch语句
- 责任链模式
- 策略模式
- 枚举
- 表驱动
