# 容器操作规范
若项目中涉及到容器相关操作, 则应该遵循一下规范.

## 容器镜像构建
- 当需要设计和实现容器镜像时, 请尽可能的使用```多阶段构建```的方式来减小镜像的大小.
- 如果需要构建的镜像容量很大时, 请在后续的构建中尽可能的不要```使用--no-cache```参数.

## 清理构建环境
当发生了build操作失败后,应该先清理一下构建环境后再执行后续的操作.相关命令参考:

- \# docker image prune
- \# docker builder prune -a

注意, 应该清理项目相关的无用镜像, 要尽可能保留用作基础镜像的相关镜像.

## 容器资源限制
在编写docker compose或启动容器时, 请根据其运行内容的特点自动为容器添加针对计算资源的限制.
这一部分建议与用户进行商讨后再进行.

## 镜像tag
- 在为最新版本的镜像添加版本号tag的同时,也需要为其添加```latest```的tag.
- Git Tag 必须与版本号一一对应：git tag -a v1.2.0 -m "Release v1.2.0"
- 使用 Signed Tag（git tag -s）确保发布来源可信
