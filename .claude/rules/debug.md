# Debug指南
本文档中记录了关于对项目进行Debug的操作规范.

## 联调测试
如果用户发了与你的联调测试, 那么你应该配合用户做以下几个方面的操作:

1. 实时跟踪项目中相关日志的更新内容
2. 实时监听整个调用链中相关服务/组件的日志的更新内容
3. 如果项目有配套的监控服务, 则应该借助监控服务来查看系统的整体状况和异常状态

注意,联调测试中的相关操作请尽可能的使用subagent来完成, 以避免过度的测试过程内容污染主session的context.


## 思路整理
当用户向你反映了一些异常问题时, 请按照以下思路来协助用户排查问题:
1. 如果用户描述的问题很模糊, 则请使用多轮对话帮助用户逐步梳理清楚问题的全貌
2. 当确定问题全貌后, 请先尝试复现问题, 并记录问题出现时的相关异常状态信息.如果你无法自行复现问题, 则可以让用户帮助你进行复现.**这一步可以重复多次,直到你认为异常信息已经收集的足够多了为止.**
3. 根据问题对应的异常信息, 以及功能的调用链或调用逻辑来定位问题根源.
4. 向用户汇报排查的具体流程以及问题的根本原因
5. 给出修复建议
6. 询问用户是否认同修复建议

## 用户反馈
如果后端服务能够成功返回异常状态, 但前端项目缺对异常状态没有做处理从而导致给用户没有任何反馈时,应该及时提醒用户先补完整前端项目中的相关用户反馈机制后,再进行debug操作.

## 容器化部署
对于容器化形式所部署的项目, 可以采取一下几种调试方式:
1. 如果需要对子功能模块进行频繁的调试操作(例如利用增加断点日志打印), 则建议使用docker cp命令进行快速的部署与调试操作.
